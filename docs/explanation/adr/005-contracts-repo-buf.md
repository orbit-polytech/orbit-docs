# ADR-005: Контракты в contracts с Buf (Go и Python, Dart через OpenAPI)

## Статус
**Принято (Accepted)** — Октябрь 2026 г.

---

## Контекст
В многоязычной распределенной системе (Go, Python, Dart/Flutter) критически важно иметь единый источник истины для контрактов API:
1. Если хранить `.proto` файлы внутри каждого микросервиса, они неизбежно рассинхронизируются.
2. Ручная установка `protoc` и плагинов компилятора (`protoc-gen-go`, `protoc-gen-go-grpc`) на машинах разработчиков с Windows, macOS и Linux часто приводит к ошибкам совместимости версий.
3. Мобильное приложение на Flutter не должно зависеть от gRPC-плагинов и тяжелых бинарных зависимостей, так как клиент общается со шлюзом по протоколу REST/JSON.

---

## Решение
Принята стратегия **Centralized Contract Repository & Buf Tooling (Единый репозиторий контрактов с инструментарием Buf)**:

1. **Единый репозиторий `contracts`:**
   Все `.proto` файлы хранятся в репозитории [`orbit-polytech/contracts`](https://github.com/orbit-polytech/contracts).
2. **Использование Buf CLI (v2):**
   - Управление версиями плагинов через `buf.gen.yaml`.
   - Автоматический линтинг Protobuf-стиля (`buf lint`).
   - Контроль обратной совместимости (`buf breaking --against ".git#branch=main"`).
3. **Генерация артефактов:**
   - **Для Go (реализовано):** код генерируется в `gen/go/`, подключается корневой модуль `github.com/orbit-polytech/contracts@v0.5.0`; импортируется пакет из `gen/go/orbit/...`. В текущем релизе — Auth и Schedule.
   - **Для Python (план):** добавить генерацию и способ доставки пакета перед реализацией `ai-service`. `gen/python/` не является текущим опубликованным артефактом.
   - **Для Dart/Flutter:** REST/JSON через Gateway. Текущая Swagger-схема генерируется Swag из HTTP-аннотаций Gateway в `api/docs`, не proto-плагином в `contracts`. Генерация клиента из этой схемы — отдельный этап мобильной разработки.

---

## Последствия

### Позитивные последствия:
- **Единый источник истины:** Никаких споров о типах данных и названиях полей — всё зафиксировано в `.proto`.
- **Защита от ломающих изменений:** GitHub Actions в `contracts` блокирует PR, если разработчик удалил поле или изменил тег существующего поля.
- **Воспроизводимость сборки:** Разработчику не нужно настраивать компилятор `protoc` вручную — Buf запускается локально или через Docker.

### Негативные последствия и компромиссы:
- **Двухэтапный процесс разработки:** Чтобы реализовать новый метод, нужно сначала смерджить PR в `contracts`, и лишь затем писать код в микросервисе.
