# Текущее состояние Orbit AI

**Проверенный срез:** `main` репозиториев после подключения AI к Gateway; версии кода приведены ниже. Проверка документации не заменяет новый запуск стенда.
**Назначение страницы:** отделить работающий код от целевой архитектуры и учебных примеров.

## Обозначения статуса

| Статус | Значение |
|---|---|
| **Работает сейчас** | Реализация находится в основном коде и проверена тестами или ручным прогоном |
| **В разработке** | Изменения находятся в feature-ветке или ещё не прошли полный релизный цикл |
| **Запланировано** | Компонент входит в целевую архитектуру, но реализация ещё не начата или не завершена |
| **Учебный пример** | Код и описание предназначены для обучения и не являются production-сервисом |

## Что проверено

Для Auth/Gateway подтверждены следующие сценарии:

- регистрация и вход по Email OTP;
- ротация refresh-сессий;
- безопасная привязка Google identity с re-auth и binding cookie;
- прямой вход через привязанную Google identity;
- получение списка identities;
- обработка истёкшего окна повторной аутентификации.

Для исходного контейнерного стенда Auth/Gateway ранее подтверждено ручным прогоном:

- `jwt-keygen` и `auth-migrate` завершаются с кодом `0`;
- PostgreSQL, Redis, Auth и Gateway переходят в состояние `healthy`;
- JWT-ключи сохраняются после `down` → `up`;
- приватный ключ доступен Auth и не монтируется в Gateway;
- `GET /healthz` возвращает `200 OK`;
- Swagger открывается по адресу `/swagger/index.html`.

## Текущая интеграция расписания

Код в `main` сверён по срезам: [Schedule `f097954`](https://github.com/orbit-polytech/schedule-service/tree/f09795432ee63649f666524b5a9c23308a4f7186), [Gateway `71c1b5e`](https://github.com/orbit-polytech/gateway-service/tree/71c1b5ecf78edc0c7d0dd541e80551086b74b086), [infra `a38f1d3`](https://github.com/orbit-polytech/infra/tree/a38f1d3ac30c3fc8e5c6bbaae66d0497187bc4b3); контракт [`v0.5.0`](https://github.com/orbit-polytech/contracts/tree/v0.5.0). Публичные маршруты поиска и чтения не требуют JWT. Без дат выбран период Пн–Вс в `Europe/Moscow`, максимальный явный интервал — 93 дня включительно. В JSON возвращаются границы запроса, `READY` / `PENDING_SYNC`, актуальность и известный период публикации. При отсутствии расписания подтверждённое фоновое задание даёт `200 PENDING_SYNC`; недоступная очередь без сохранённых данных — `503`. Redis-кэш общий для группы, при его сбое чтение переходит в PostgreSQL. Подробности — [API расписания](../gateway/schedule-api.md).

Изменения прошли проверки сервисов до слияния. Новый Docker/E2E-прогон при обновлении этой документации не выполнялся; наличие кода в `main` не подтверждает доступность private-пакетов конкретному участнику или готовность расписания всех групп. Healthcheck и синхронизация данных — разные проверки.

## Текущая интеграция AI

Код сверен: [AI `0d0fff1`](https://github.com/orbit-polytech/ai-service/tree/0d0fff1de43267260f6d2cef4657d48e06c9183d), [Gateway `d8f0766`](https://github.com/orbit-polytech/gateway-service/tree/d8f0766669b6e12bc007bea4f5dc039e015bf204), [infra `8723bca`](https://github.com/orbit-polytech/infra/tree/8723bca7e83e2664b6ac0c2c2f6722fa1a1d9892), [contracts `dfad498`](https://github.com/orbit-polytech/contracts/tree/dfad498af6e49658c619a33955c0926fc557464b).

- `POST /api/v1/ai/chat/stream` и `/api/v1/ai/chat/cancel` требуют JWT.
- Gateway передаёт проверенный `x-user-id`; AI проверяет владение диалогом, повтором ответа и активной генерацией. Users для этого не нужен: идентичность выдаёт Auth.
- Groq генерирует ответ; FastEmbed вычисляет эмбеддинги; RAG ищет только в активных версиях документов PostgreSQL/pgvector.
- Успешный результат сохраняется и может быть выдан повторно без новой генерации. После ошибки/отмены нужна новая попытка с новым `message_id`.
- Полноценная история в prompt, инструменты чтения расписания и распределённая отмена между репликами пока не реализованы. `--demo` загружает тестовые тексты, не проверенную базу официальных актов.

Подробности: [AI API](../gateway/ai-api.md), [запуск с AI](../how-to/ai-local-stack.md), [база знаний](../python-ai/knowledge-ingestion.md). Наличие кода/тестов в репозитории не означает, что при этом обновлении заново проверены CI, GHCR, качество ответов или чистый Docker-запуск.

## Ближайшие шаги

1. Проверить Read-доступ к шести пакетам базового стенда и к `ai-service` для AI-профиля.
2. Выполнить чистый запуск `apps`, затем `all`, и smoke test защищённого AI API.
3. Наполнить базу знаний проверенными документами, оценить поиск и корректность цитат на контрольных вопросах.
4. Проверить изоляцию пользователей, replay, отмену, ошибки провайдера и поведение при пустой базе.
5. Развивать расписание отдельно: сессия, преподаватели, аудитории и клиентские фильтры не считаются реализованными автоматически.

!!! warning "Текущее и целевое"
    RabbitMQ, Jaeger, Telegram-вход, production Tasks/Users и мобильное приложение остаются целевой архитектурой или учебными примерами. AI уже реализован, но его ограничения описываются отдельно от будущих возможностей.
