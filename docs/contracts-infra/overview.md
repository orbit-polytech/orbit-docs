# Контракты и Инфраструктура: API-First подход

В основе надежности микросервисной архитектуры Orbit AI лежат два базовых принципа:
1. **API-First (Сначала контракты)**: любые изменения во взаимодействии микросервисов начинаются с описания схемы в репозитории [**`contracts`**](https://github.com/orbit-polytech/contracts). Ни один разработчик не пишет код сервиса, пока схема интерфейса не согласована и не проверена линтером `buf`.
2. **Единое окружение разработки**: текущий согласованный стек поднимается одной командой через репозиторий [**`infra`**](https://github.com/orbit-polytech/infra).

---

## 1. Репозиторий `contracts`

Вместо того чтобы копировать `.proto` файлы вручную между репозиториями сервисов, все схемы Protobuf v3 централизованно хранятся в `contracts`.

С помощью **Buf CLI** схемы валидируются и проверяются на обратную совместимость. В `contracts@v0.4.0` находятся Auth и Schedule, генерируется Go-код в `gen/go/`. Сервисы подключают корневой модуль `github.com/orbit-polytech/contracts@v0.4.0`, а импортируют конкретный пакет из `gen/go/orbit/...`. Python-генерация и новые контракты добавляются отдельно. См. [дерево и команды](contracts.md).

---

## 2. Репозиторий `infra`

Репозиторий `infra` поднимает PostgreSQL 16, Redis 7, Auth, Schedule, Gateway, keygen, provisioner и миграторы. `task up` включает профиль `apps`; без профиля запускаются только базовые зависимости. `all` также включает приложения. Профилей `core`/`ai` и `compose.debug.yaml` в текущей конфигурации нет.

Базовый Compose использует готовые GHCR-образы без исходников соседних сервисов. Локальная сборка включается через `compose.override.yaml`. gRPC порты Auth и Schedule доступны на loopback для диагностики. RabbitMQ, Jaeger и pgvector — будущие этапы, не скрытые зависимости текущего стенда.

Далее: [актуальный infra](infra.md), [порты](../reference/ports-and-env.md), [доступ к private-пакетам](../quickstart/ghcr-access.md).
