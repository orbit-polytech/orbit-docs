# Контракты и Инфраструктура: API-First подход

В основе надежности микросервисной архитектуры Orbit AI лежат два базовых принципа:
1. **API-First (Сначала контракты)**: любые изменения во взаимодействии микросервисов начинаются с описания схемы в репозитории [**`contracts`**](https://github.com/orbit-polytech/contracts). Ни один разработчик не пишет код сервиса, пока схема интерфейса не согласована и не проверена линтером `buf`.
2. **Единое окружение разработки**: вся инфраструктура (базы данных, очереди, трейсинг) поднимается одной командой через репозиторий [**`infra`**](https://github.com/orbit-polytech/infra).

---

## 1. Репозиторий `contracts`

Вместо того чтобы копировать `.proto` файлы вручную между репозиториями сервисов, все схемы Protobuf v3 централизованно хранятся в `contracts`.

С помощью инструмента **Buf CLI** схемы валидируются на правила оформления и проверяются на обратную совместимость (breaking change detection). Сгенерированный код на Go и Python коммитится прямо в репозиторий `contracts` в папки `gen/go/` и `gen/python/`, откуда микросервисы подключают его как стандартный Go-модуль (`go get github.com/orbit-polytech/contracts/gen/go/...`) или пакет Python.

---

## 2. Репозиторий `infra`

Репозиторий `infra` изолирует всю сложность локального окружения:
* Единый файл `compose.yaml` поднимает **PostgreSQL 16 с расширением pgvector**, **Redis 7**, **RabbitMQ 4** и сервер трассировки **Jaeger**.
* Сервисы разбиты по профилям (`--profile core`, `--profile ai`, `--profile all`), позволяя разработчикам запускать только те компоненты, которые нужны для их текущей задачи.
* Файл `compose.debug.yaml` пробрасывает gRPC-порты наружу на `127.0.0.1` для прямой отладки через `grpcurl` и GUI-клиенты.
