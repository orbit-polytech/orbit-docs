# Публичное API расписания

Реализовано в `main` репозиториев `schedule-service` и `gateway-service`, контракт — `contracts@v0.5.0` (`orbit.schedule.v1`). Это справочник текущего поведения, а не проект будущего API.

## Доступ и первый запрос

Расписание доступно **без регистрации и без Bearer JWT**. Профиль Users не нужен. Для получения данных достаточно названия группы:

```bash
curl "http://localhost:8080/api/v1/schedule/groups/261-334"
```

В PowerShell при наличии alias `curl` используйте `curl.exe`. При изменённом `GATEWAY_HOST_PORT` замените порт в URL.

Сервис вернёт текущую календарную неделю: понедельник–воскресенье в `Europe/Moscow`. Это не весь семестр и не «ближайшие семь дней». Клиенту не нужно вычислять даты для первого открытия расписания.

## Поиск групп

```http
GET /api/v1/schedule/groups?query=261&limit=20
```

| Параметр | Правило |
|---|---|
| `query` | Необязательная строка поиска по названию группы |
| `limit` | По умолчанию `20`; положительное целое; значения больше `100` ограничиваются до `100` |

Пример формы ответа (данные иллюстративные):

```json
{
  "groups": [
    {
      "title": "261-334",
      "has_regular_schedule": true,
      "has_session_schedule": false
    }
  ]
}
```

Это ограниченный список, не постраничный API: cursor, offset и total в текущем контракте отсутствуют. Признаки наличия расписания не гарантируют, что расписание уже загружено локально. `has_session_schedule` не означает наличия endpoint для сессии.

## Расписание группы и выбор дат

```http
GET /api/v1/schedule/groups/{group}
```

`group` — название группы, например `261-334`, а не UUID. Даты — календарные строки `YYYY-MM-DD`.

| Переданные параметры | Результат |
|---|---|
| Без дат | Текущая неделя по Москве, Пн–Вс |
| Только `date_from` | Один день: обе границы равны `date_from` |
| `date_from` и `date_to` | Указанный интервал, обе границы включены |
| Только `date_to` | `400 INVALID_ARGUMENT` |
| Некорректная/несуществующая дата | `400 INVALID_ARGUMENT` |
| Начало позже конца | `400 INVALID_ARGUMENT` |
| Более `93` календарных дней включительно | `400 INVALID_ARGUMENT` |

Пробелы по краям параметров обрезаются; пустые строки считаются отсутствующими. Максимум — **93**, не 31 день. Параметр `preset` и endpoint `/grid` не поддерживаются.

```bash
# Один день
curl "http://localhost:8080/api/v1/schedule/groups/261-334?date_from=2026-10-24"

# Явная неделя
curl "http://localhost:8080/api/v1/schedule/groups/261-334?date_from=2026-10-19&date_to=2026-10-25"

# Ошибка: конец без начала
curl -i "http://localhost:8080/api/v1/schedule/groups/261-334?date_to=2026-10-25"
```

Прошедшая дата допустима по формату, но API не гарантирует архив всех прошлых версий расписания: чтение строится по текущей сохранённой версии расписания.

## Форма ответа

Пример иллюстрирует схему, не реальное расписание группы:

```json
{
  "group_title": "261-334",
  "evening_type": 0,
  "metadata": {
    "last_checked_at": "2026-10-24T12:00:00Z",
    "last_updated_at": "2026-10-24T10:00:00Z",
    "is_stale": false,
    "status": "READY",
    "published_from": "2026-09-01",
    "published_to": "2026-12-31"
  },
  "days": [
    {
      "date": "2026-10-19",
      "day_of_week": 1,
      "lessons": [
        {
          "subject": "Пример дисциплины",
          "type": "Лекция",
          "slot_number": 1,
          "start_time": "09:00",
          "end_time": "10:30",
          "auditoriums": [{"name": "А-101"}],
          "teachers": [{"name": "Пример преподавателя"}]
        }
      ]
    }
  ],
  "time_zone": "Europe/Moscow",
  "date_from": "2026-10-19",
  "date_to": "2026-10-25"
}
```

- `date_from` / `date_to` — фактически выбранные границы, в том числе при пустом `days`. Клиент отображает их, а не угадывает по первому и последнему занятию.
- `day_of_week`: понедельник `1`, воскресенье `7`. `start_time` / `end_time` — локальное время пар в `time_zone`, а не UTC timestamp.
- `evening_type` и `slot_number` используются сервисом для выбора сетки звонков.
- `last_checked_at` и `last_updated_at` — RFC 3339 timestamps; могут отсутствовать, если значения не заданы. Сама календарная дата не должна смещаться при преобразовании часовых поясов на клиенте.
- У занятия также возможны `location`, `e_link`, `week`; у аудитории — `web_url` и `color`, у преподавателя — `id`. Необязательные поля могут отсутствовать.
- `days` содержит только даты с занятиями, не все дни периода. Для пустых календарных ячеек клиент использует границы `date_from`/`date_to`.
- Сохранённый пустой результат — `200`, не ошибка транспорта. Не следует считать пустой `days` доказательством отсутствия группы.

## Состояния расписания

`metadata.status` отделяет готовое расписание от ожидания загрузки:

| Ситуация | HTTP / состояние | Поведение клиента |
|---|---|---|
| Расписание сохранено | `200`, `READY` | Показать занятия; пустой `days` допустим |
| Расписание устарело | `200`, `READY`, `is_stale=true` | Показать данные и отметку актуальности; обновление идёт в фоне |
| Расписание ещё не загружено, задание подтверждено | `200`, `PENDING_SYNC` | Показать ожидание и повторить запрос с задержкой, не в тесном цикле |
| Нет данных и очередь недоступна | `503`, `UNAVAILABLE` | Показать временную недоступность |
| Группа неизвестна | `404`, `NOT_FOUND` | Предложить проверить название |

Пример ожидания (выбранные даты иллюстративные):

```json
{
  "group_title": "261-334",
  "evening_type": 0,
  "metadata": {"status": "PENDING_SYNC", "is_stale": false},
  "days": [],
  "time_zone": "Europe/Moscow",
  "date_from": "2026-10-19",
  "date_to": "2026-10-25"
}
```

Неизвестные даты проверки и публикации могут отсутствовать. `UNSPECIFIED` — неизвестное состояние, в том числе при старой версии upstream или неизвестном enum; клиент не должен автоматически считать его `READY` или `PENDING_SYNC`.

`published_from` / `published_to` — известные границы опубликованного расписания. Они отличаются от выбранного диапазона `date_from` / `date_to`. Запрос за пределами публикации не доказывает каникулы или выходной. `READY` с пустым `days` не равен ожиданию загрузки и не означает отсутствия группы. API не вводит отдельный статус `OUT_OF_BOUNDS`.

## Ошибки и диагностика

| HTTP | `error.code` | Значение |
|---|---|---|
| `400` | `INVALID_ARGUMENT` | Неверные параметры или диапазон |
| `404` | `NOT_FOUND` | Группа не найдена в локальном реестре |
| `503` | `UNAVAILABLE` | Недоступен gRPC upstream либо нет расписания и невозможно поставить обновление |
| `504` | `DEADLINE_EXCEEDED` | Истёк таймаут обращения к Schedule |
| `500` | `INTERNAL` | Непредвиденная ошибка |

Gateway скрывает внутреннюю причину `503`. Сохраните `X-Request-ID` и проверьте логи без публикации секретов:

```bash
# Из infra
 task status
 docker compose --profile apps logs --tail 100 schedule-migrate schedule-service gateway-service
```

`healthy` не означает готовность расписания всех групп. Проверьте `SCHEDULE_SYNC_ENABLED`, доступность Redis и источника. Изменение env требует пересоздания контейнера (`task up`), одного `docker compose restart` недостаточно.

HTTP/gRPC-запрос может поставить задание в приоритетную очередь, но не скачивает данные источника синхронно. Увеличение диапазона дат не ускоряет загрузку. Повторные запросы группы используют общие сохранённые данные; каждому студенту не требуется отдельная синхронизация.

## Ограничения текущего среза

Регулярное расписание групп, календарная фильтрация по интервалам дат, сохранение параллельных занятий, Redis-кэш и фоновое обновление по запросу реализованы. Поиск по преподавателю/аудитории, сессия, API-фильтр подгрупп, универсальная фильтрация чётности, presets и отдельная сетка семестра — будущие этапы.
