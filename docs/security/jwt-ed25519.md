# JWT и асимметричная подпись Ed25519

В этом разделе детально объясняется, как устроен механизм авторизации Orbit AI, почему мы выбрали асимметричную подпись **Ed25519 (EdDSA)** и как правильно валидировать JWT.

---

## 1. Сравнение симметричной (HS256) и асимметричной (Ed25519) подписи

В простых учебных проектах часто используют симметричную подпись `HS256`, где для подписи и проверки используется один общий секретный пароль (`JWT_SECRET`).

**Почему в микросервисах HS256 опасен:**
При симметричной подписи `auth-service` и `gateway-service` обязаны знать один и тот же секретный ключ. Если скомпрометирован Gateway, злоумышленник получает возможность не только читать чужие токены, но и **самостоятельно выпускать валидные токены администратора** от имени любого студента!

**Почему мы выбрали Ed25519 (`EdDSA`):**
1. **Асимметрия**: Приватный ключ (`jwt_ed25519`) хранится **исключительно в `auth-service`**. Ни один другой сервис или шлюз к нему доступа не имеет.
2. `gateway-service` получает только **публичный ключ** (`jwt_ed25519.pub`). Шлюз может быстро проверять подпись входящих запросов, но физически не способен подписать поддельный токен.
3. **Скорость и безопасность**: алгоритм Ed25519 работает значительно быстрее устаревшего RSA, использует 32-байтные компактные ключи и математически защищён от атак по побочным каналам.

## 2. Разделение Access и Refresh токенов

| Характеристика | Access Token | Refresh Token |
|---|---|---|
| **Формат** | JSON Web Token (JWT) с подписью Ed25519 | Криптографически случайная строка (32 байта, base64url) |
| **Срок действия** | **15 минут** (короткоживущий) | **30 дней** (скользящий) |
| **Где проверяется** | В `gateway-service` локально по открытому ключу (без похода в БД) | Только в `auth-service` по базе данных PostgreSQL |
| **Хранение на бэкенде**| Сервер не хранит выпущенные токены (stateless) | В БД хранится только `SHA-256(refresh_token)` |
| **Возможность отзыва** | Истекает сам через 15 минут | Можно мгновенно отозвать при выходе из аккаунта |

> [!NOTE]
> Refresh-токен **намеренно не является JWT**. Это случайная непрозрачная строка (Opaque Token). Её невозможно подделать, а в базе хранится только её криптографический хэш.

## 3. Структура Payload Access-токена

```json
{
  "iss": "orbit-auth",
  "aud": "gateway-service",
  "sub": "0192c6b1-9a72-7a8e-a204-c38d58f3b201",
  "role": "student",
  "sid": "0192c6b2-ef44-7123-9988-d44a2b91c102",
  "iat": 1760000000,
  "exp": 1760000900,
  "jti": "0192c6b3-1122-3344-5566-778899aabbcc"
}
```

* `iss` (Issuer): издатель токена (`orbit-auth`).
* `aud` (Audience): целевой потребитель (`gateway-service`).
* `sub` (Subject): внутренний UUID студента в системе.
* `role`: роль пользователя (`student`, `teacher`, `admin`).
* `sid`: идентификатор сессии входа.
* `exp`: время истечения (ровно 15 минут от `iat`).
* `jti`: уникальный идентификатор конкретного токена.

Заголовок токена (Header):
```json
{
  "alg": "EdDSA",
  "typ": "at+jwt",
  "kid": "2026-10"
}
```
Поле `typ: "at+jwt"` явно декларирует, что данный JWT является именно Access Token'ом, предотвращая атаку подмены типа токена (RFC 9068).

## 4. Безопасная проверка токена в Gateway (`verifier.go`)

```go
package authjwt

import (
	"crypto/ed25519"
	"errors"
	"fmt"

	"github.com/golang-jwt/jwt/v5"
)

type Claims struct {
	Role      string `json:"role"`
	SessionID string `json:"sid"`
	jwt.RegisteredClaims
}

type Verifier struct {
	publicKey ed25519.PublicKey
	issuer    string
	audience  string
}

func NewVerifier(pubKey ed25519.PublicKey, issuer, audience string) *Verifier {
	return &Verifier{publicKey: pubKey, issuer: issuer, audience: audience}
}

func (v *Verifier) VerifyToken(rawToken string) (*Claims, error) {
	token, err := jwt.ParseWithClaims(
		rawToken,
		&Claims{},
		func(t *jwt.Token) (any, error) {
			// ЗАЩИТА: проверяем, что алгоритм именно EdDSA
			if t.Method.Alg() != jwt.SigningMethodEd25519.Alg() {
				return nil, fmt.Errorf("недопустимый алгоритм подписи: %v", t.Header["alg"])
			}
			return v.publicKey, nil
		},
		jwt.WithIssuer(v.issuer),
		jwt.WithAudience(v.audience),
		jwt.WithValidMethods([]string{"EdDSA"}), // Жесткое ограничение
	)
	if err != nil {
		return nil, fmt.Errorf("токен не прошел проверку: %w", err)
	}

	claims, ok := token.Claims.(*Claims)
	if !ok || !token.Valid {
		return nil, errors.New("недействительный токен")
	}

	return claims, nil
}
```
