# Модель безопасности Orbit AI

Безопасность студенческого сервиса имеет первостепенное значение: утечка персональных данных студентов или возможность подделать результаты лабораторных работ и оценок недопустимы.

---

## 1. Разделение ответственности за безопасность

| Компонент | Зона ответственности |
|---|---|
| [**`auth-service`**](https://github.com/orbit-polytech/auth-service) | Вход через Telegram, верификация `initData`, выпуск и отзыв токенов, хранение сессий, приватный ключ подписи Ed25519 |
| [**`gateway-service`**](https://github.com/orbit-polytech/gateway-service) | Проверка валидности access-токена по публичному ключу Ed25519, rate limiting, очистка входящих служебных заголовков |
| **Микросервисы** | Авторизация конкретных бизнес-ресурсов («является ли текущий студент владельцем этой задачи?») |
| [**`mobile`**](https://github.com/orbit-polytech/mobile) | Защищённое хранение токенов в системном Keychain / KeyStore |

> [!IMPORTANT]
> **Аутентификация** (проверка того, кто пришел) происходит на уровне `gateway-service` и `auth-service`.
> **Авторизация** (проверка того, что пользователю разрешено делать) происходит **всегда внутри целевого микросервиса**. Gateway не знает и не должен знать, чья это задача.

---

## 2. Верификация входа через Telegram

Основной способ входа в систему — Telegram (Telegram Login Widget на сайте и `initData` в Telegram Mini App).

### Проверка подписи Telegram Login Widget
Telegram передает клиенту набор полей: `id`, `first_name`, `username`, `photo_url`, `auth_date`, `hash`.

Алгоритм криптографической проверки в `auth-service`:
1. Из полей формируется строка проверки `data_check_string`: все поля, кроме `hash`, сортируются по имени в алфавитном порядке и объединяются в виде `key=value\n`.
2. Секретный ключ вычисляется как хэш токена бота: `secret_key = SHA256(bot_token)`.
3. Ожидаемая подпись вычисляется через HMAC-SHA256: `expected = hex(HMAC_SHA256(data_check_string, secret_key))`.
4. Полученный от клиента `hash` и `expected` сравниваются **за постоянное время** (`hmac.Equal`) для защиты от атак по времени (Timing Attacks).
5. Временная метка `auth_date` проверяется на свежесть: она не может быть старше **5 минут**. Это защищает от атак повторного воспроизведения (Replay Attacks).

### Проверка Telegram Mini App (`initData`)
В Mini App логика идентична, за исключением вычисления ключа:
`secret_key = HMAC_SHA256(key="WebAppData", message=bot_token)`.

> [!CAUTION]
> Клиентский объект `initDataUnsafe` никогда не используется на бэкенде для авторизации: злоумышленник может отредактировать в нём любые данные в браузере. Проверяется только сырая криптографически подписанная строка `initData`.
