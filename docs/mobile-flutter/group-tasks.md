# Серверные групповые задачи и Режим Старосты

> **Архитектурный статус фичи:** `[Запланировано]`  
> Данный модуль проектируется как серверное расширение функционала задач в связке с микросервисами `tasks-service` и `users-service`.

Модуль групповых задач решает проблему разобщенности учебных требований: необходимость старост ежедневно дублировать домашние задания, дедлайны и методички в неструктурированные чаты в Telegram/VK.

---

## 1. Разграничение понятий: Личные vs Групповые задачи

В архитектуре данных строго разделяются понятия **области доступа (Scope)** и **места хранения (Storage)**:

| Область доступа | Кто видит задачу | Место хранения | Требование авторизации |
| :--- | :--- | :--- | :--- |
| **`TaskScope.personal`** | Только сам студент | Локально в Hive (гость) или синхронизируется с облаком (после входа) | Не требуется (доступно в гостевом режиме) |
| **`TaskScope.group`** | Все подтвержденные студенты группы | База данных `tasks-service` + локальный кэш Hive | Обязательна авторизация через Email OTP или Google |

---

## 2. Ролевая модель и проверка прав

### Подтверждение группы и роли:
1. **Принадлежность к группе:** На текущем этапе студент выбирает свою группу самостоятельно при онбординге или в профиле. Автоматическая верификация через деканат / ЛК Политеха находится в статусе `[Проектируется]`.
2. **Роль старосты (`headman`):** Подтверждается на сервере `users-service`. При успешной проверке токен пользователя содержит JWT Claim:
   ```json
   {
     "sub": "usr_948192",
     "group": "261-334",
     "role": "headman"
   }
   ```
3. **Права на создание:** Создавать и редактировать групповые задания могут только пользователи с подтвержденной ролью `headman` внутри своей группы. Студенты группы имеют доступ только на чтение и отметку личного прогресса сдачи.

## 3. Семантика отметки о сдаче (Submission Semantics)

> **Важное разграничение:**  
> Отметка «Сдано» внутри мобильного приложения Orbit — это **личный самоотчет студента**, предназначенный для самоконтроля и координации внутри группы. Официальное выставление баллов в ведомость БРС производит исключительно преподаватель на портале университета.

### Дашборд старосты:
Авторизованный староста видит сводный аналитический прогресс по каждому выданному заданию:
* **Индикатор выполнения:** `📊 22/28 отметили выполнение (78%)`.
* **Список группы:** Разделение на вкладки *«Отметили сдачу (22)»* и *«Не отметили выполнение (6)»*.
* **Напоминание:** По явному запросу старосты приложение формирует текстовый дайджест для отправки в беседу:
  ```text
  📢 Лабораторная работа №3 (Базы данных)
  ⏰ Дедлайн: завтра в 14:00
  📎 Подробности и методичка в приложении Orbit Polytech
  ```
  *Примечание:* Публикация пофамильных списков студентов по умолчанию отключена для соблюдения приватности и может настраиваться старостой индивидуально.

---

## 4. Жизненный цикл и выход из группы

* **Смена группы студентом:** Если студент переводится в другую группу, групповые задачи старой группы архивируются и скрываются. Загружаются задачи новой группы. Все личные задачи (`TaskScope.personal`) сохраняются.
* **Смена старосты:** При переизбрании старосты созданные групповые задания сохраняются в базе данных группы, а права управления передаются новому старосте через `users-service`.
