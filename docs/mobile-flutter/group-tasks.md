# Серверные групповые задачи и Режим Старосты

> **Архитектурный статус фичи:** `[Запланировано]`  
> Данный модуль проектируется как серверное расширение функционала задач в связке с микросервисами `tasks-service` и `users-service`.

Модуль групповых задач решает одну из ключевых болей студенческого сообщества: необходимость старост ежедневно дублировать домашние задания, дедлайны и методички в неструктурированные чаты старостата в Telegram/VK.

---

## 1. Разграничение понятий: Личные vs Групповые задачи

В архитектуре данных строго разделяются понятия **области доступа (Scope)** и **места хранения (Storage)**:

| Область доступа | Кто видит задачу | Место хранения | Требование авторизации |
| :--- | :--- | :--- | :--- |
| **`TaskScope.personal`** | Только сам студент | Локально в Hive (гость) или синхронизируется с облаком (после входа) | Не требуется (работает в гостевом режиме) |
| **`TaskScope.group`** | Все подтвержденные студенты группы | Удаленная база данных `tasks-service` + локальный кэш Hive | Обязательна авторизация через ЛК Политеха |

---

## 2. Ролевая модель и проверка прав

### Подтверждение группы и роли:
1. **Принадлежность к группе:** Определяется автоматически при входе через Личный кабинет Московского Политеха на основе данных из деканата.
2. **Роль старосты (`headman`):** Назначается через `users-service`. При успешной проверке токен пользователя содержит JWT Claim:
   ```json
   {
     "sub": "usr_948192",
     "group": "261-334",
     "role": "headman"
   }
   ```
3. **Права на создание:** Создавать и редактировать групповые задания могут только пользователи с ролью `headman` или `deputy_headman` внутри своей группы. Студенты группы имеют доступ только на чтение и отметку личного прогресса сдачи.

---

## 3. Семантика отметки о сдаче (Submission Semantics)

> **Важное разграничение:**  
> Отметка «Сдано» внутри мобильного приложения Orbit — это **личный самоотчет студента**, предназначенный для самоконтроля и координации внутри группы. Официальное выставление баллов в ведомость БРС производит исключительно преподаватель на портале университета.

### Дашборд старосты:
Авторизованный староста видит сводный аналитический прогресс по каждому выданному заданию:
* **Индикатор сдачи:** `📊 22/28 сдали (78%)`.
* **Список группы:** Разделение на вкладки *«Сдали (22)»* и *«Должники (6)»*.
* **Быстрое напоминание:** Кнопка *«Скопировать для беседы группы»* формирует лаконичный текстовый дайджест для отправки в Telegram:
  ```text
  📢 Лабораторная работа №3 (Базы данных)
  ⏰ Дедлайн: завтра в 14:00
  ❌ Еще не сдали: Иванов, Петров, Сидоров...
  📎 Требования в приложении Orbit Polytech
  ```

---

## 4. Жизненный цикл и выход из группы

* **Смена группы студентом:** Если студент переводится в другую академическую группу, групповые задачи старой группы архивируются и скрываются из активного списка. Загружаются задачи новой группы. Все личные задачи (`TaskScope.personal`) остаются нетронутыми.
* **Смена старосты:** При переизбрании старосты созданные ранее групповые задания сохраняются в базе данных группы, а права на их редактирование передаются новому старосте через `users-service`.
