# База знаний: загрузка и версии документов

## Что уже реализовано

`DocumentIngestor` принимает подготовленный текст, разделы, название, URL и стабильный `source_id`. Он вычисляет эмбеддинги и публикует версию документа в PostgreSQL. Неизменённое содержимое с тем же составным хешем не дублируется; новая версия деактивирует прежнюю. RAG использует только фрагменты активных документов.

Публикация защищена транзакцией, advisory lock по источнику и частичным уникальным индексом активной версии. Краулер собирает выбранные страницы сайта, но сам по себе не подтверждает актуальность и достоверность всех сведений; за проверку содержания отвечает команда.

## Сбор и загрузка Markdown

Из корня клона `ai-service` после `uv sync --locked`:

```bash
# Получить HTML и подготовить Markdown из заданных разделов сайта.
uv run python -m orbit_ai.scripts.polytech_crawler

# Проверить найденные документы без записи в БД.
uv run python -m orbit_ai.scripts.ingest_documents --dir data/knowledge --dry-run

# После проверки материалов загрузить их в настроенную базу.
uv run python -m orbit_ai.scripts.ingest_documents --dir data/knowledge
```

Краулер по умолчанию пишет Markdown в `data/knowledge`, снимки HTML — в `data/raw_html`; поддерживает `--output-dir`, `--raw-dir` и `--concurrency`. В целях сбора есть МФЦ, стипендии, общежития, учебные вопросы, адреса и спортивная деятельность. Проверяйте лог и число собранных страниц: успешный код завершения возможен даже при ошибке части разделов. Ссылки на PDF извлекаются, но их содержимое автоматически не разбирается.

Перед ingestion настройте `DATABASE_URL` для нужной БД, подготовьте pgvector и примените миграции. `--dry-run` не записывает документы, но всё равно требует настроенный DSN и инициализирует модель FastEmbed; это не проверка успешной записи в БД. Флаг `--demo` больше не поддерживается. Повторная загрузка неизменённых документов пропускает их; при изменении публикуется новая версия. Проверяйте журнал загрузки и контрольные вопросы.

Docker-образ AI не включает каталог `data/knowledge`. Поэтому не запускайте ingestion в контейнере, ожидая, что файлы из клона появятся там автоматически: запустите команду из исходников с доступной БД или отдельно подключите проверенный каталог в контейнер и укажите его через `--dir`. Адрес PostgreSQL различается на хосте и в сети Compose: [локальный стенд](../how-to/ai-local-stack.md).

## Как готовить реальные материалы

Эти проверки применяются и к материалам краулера, и к документам, подготовленным вручную:

1. Найти первоисточник, проверить дату, редакцию, область действия и доступность ссылки.
2. Назначить стабильный `source_id`; обновление того же документа не должно получать случайный новый идентификатор.
3. Подготовить очищенный текст и осмысленные разделы, исключить персональные/секретные данные.
4. Использовать ту же модель, размерность и обработку эмбеддингов, что и при поиске. Смена модели требует плана переиндексации.
5. Проверить контрольные вопросы, нерелевантные запросы, цитаты, замену версии и повторную загрузку.
6. Публиковать только после проверки содержания. Порог similarity сам по себе не подтверждает корректность ответа.

## Проверка изменений

Интеграционные тесты направляются через `POSTGRES_TEST_DSN` в выделенную `orbit_ai_test` после применения миграций к ней. Проверяйте отсутствие дублей, атомарность обновления, конкурентную загрузку, исключение старых фрагментов и равенство replay. Не запускайте такие тесты на `orbit_ai`.
