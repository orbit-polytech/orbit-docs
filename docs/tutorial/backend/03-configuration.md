# 03. Конфигурация сервиса (.env и флаги)

В соответствии с третьим фактором методологии [The Twelve-Factor App](https://12factor.net/config) (III. Config), вся конфигурация микросервисов Orbit AI передаётся **исключительно через переменные окружения**.

Конфигурация никогда не зашивается в исходный код, а при старте сервиса выполняется строгая проверка значений по принципу **Fail-Fast**.

---

## 1. Структура конфигурации `Config`

Вся конфигурация инкапсулирована в пакете `internal/config/config.go`. Структура `Config` объединяет параметры запуска и константы допустимых значений:

```go
--8<-- "examples/tasks-service/internal/config/config.go:config_struct"
```

### Основные переменные окружения:

| Переменная | Назначение | Значение по умолчанию | Допустимые значения |
| :--- | :--- | :--- | :--- |
| `GRPC_PORT` | Сетевой порт gRPC-сервера | `50051` | Целое число от `1` до `65535` |
| `APP_ENV` | Окружение развёртывания | `development` | `development`, `staging`, `production` |
| `LOG_LEVEL` | Уровень детализации логов | `info` | `debug`, `info`, `warn`, `error` |

---

## 2. Принцип Fail-Fast и защита от тихих ошибок

Распространённая ошибка при разработке сервисов — использование «тихих дефолтов» при некорректно переданных значениях (например, падение в `info`, если в `LOG_LEVEL` передана опечатка `inf`).

В продакшене это приводит к катастрофическим последствиям: сервис запускается не на том порту, пишет отладочные логи в боевую базу или подключается к тестовому контуру.

### Правило Orbit AI:
> Если значение переменной окружения задано некорректно, `config.Load()` возвращает понятную ошибку, а функция `main()` немедленно завершает процесс с ненулевым кодом выхода.

```go
// cmd/tasks-service/main.go
cfg, err := config.Load()
if err != nil {
    logger.Error("ошибка инициализации конфигурации", slog.String("error", err.Error()))
    os.Exit(1)
}
```

## 3. Модульное тестирование конфигурации

Пакет `internal/config` изолирован от внешних слоёв и полностью покрыт табличными тестами:

```go
--8<-- "examples/tasks-service/internal/config/config_test.go:config_tests"
```

### Почему используется `t.Setenv`:
Метод `t.Setenv(key, value)` устанавливает переменную окружения только на время выполнения текущего теста и автоматически восстанавливает исходное значение после его завершения. Это гарантирует изоляцию тестов при параллельном запуске.

## 4. Антипаттерны: как нельзя и как правильно

### ❌ Как нельзя:
```go
// ОШИБКА 1: Чтение os.Getenv раскидано по бизнес-логике
func (h *Handler) Handle() {
    port := os.Getenv("PORT") // Нарушение: транспорт лезет в переменные ОС
}

// ОШИБКА 2: Игнорирование ошибки парсинга порта
port, _ := strconv.Atoi(os.Getenv("PORT")) // Если в PORT строка "abc", port станет 0

// ОШИБКА 3: Паника при ошибке конфигурации
if port == 0 {
    panic("port is required") // Паника скрывает причину и ломает тесты
}
```

### ✅ Как правильно:
```go
// Конфигурация собирается единожды в точке входа (main)
cfg, err := config.Load()
if err != nil {
    return fmt.Errorf("загрузка конфигурации: %w", err)
}

// Порт валидируется по диапазону 1..65535
if port <= 0 || port > 65535 {
    return nil, fmt.Errorf("некорректный GRPC_PORT %q: ожидается порт от 1 до 65535", portStr)
}

// Передача параметров зависимостям через конструкторы
server := taskgrpc.NewServer(cfg.GRPCPort, logger)
```

---

## Резюме

1. **Единая точка входа**: вся конфигурация загружается один раз в `cmd/.../main.go` через `config.Load()`.
2. **Fail-Fast**: сервис никогда не стартует с невалидной конфигурацией.
3. **Изоляция**: ни один внутренний слой (`domain`, `usecase`) не вызывает `os.Getenv`.
