# 6.1 Доменный слой (Domain)

Доменный слой — это сердце микросервиса. Здесь сосредоточены ключевые бизнес-правила и инварианты системы.

В архитектуре Orbit AI к пакету `internal/domain` предъявляется наиболее строгое требование: **абсолютная изоляция от внешнего мира**. Код домена зависит **исключительно от стандартной библиотеки Go (`$gostd`)**.

---

## 1. Доменные ошибки (Sentinel Errors)

Все бизнес-ошибки объявляются в начале файла как неизменяемые переменные. Это позволяет слоям Use Case и Transport однозначно идентифицировать причину сбоя:

```go
--8<-- "examples/tasks-service/internal/domain/task.go:domain_errors"
```

Каждая ошибка фиксирует конкретное нарушение бизнес-правила:
- `ErrEmptyTitle`: название задачи не указано или состоит только из пробелов;
- `ErrTitleTooShort`: длина заголовка менее 3 символов;
- `ErrInvalidDeadline`: дедлайн установлен в прошлом;
- `ErrTaskAlreadyCompleted`: попытка перенести дедлайн или завершить задачу, которая уже закрыта;
- `ErrVersionConflict`: конфликт параллельного редактирования.

---

## 2. Value Objects (Объекты-значения)

Вместо примитивных типов (`string`, `int`) домен использует **Value Objects** (DDD паттерн). Это исключает антипаттерн *Primitive Obsession* — ситуацию, когда два строковых параметра случайно путаются местами в аргументах функции:

```go
// Опасно (Primitive Obsession):
func Assign(taskID string, ownerID string) // Можно случайно передать Assign(ownerID, taskID)

// Безопасно (Value Objects):
func Assign(taskID domain.TaskID, ownerID domain.OwnerID) // Ошибка выявится на этапе компиляции!
```

Ниже представлен код объектов-значений `TaskID`, `OwnerID`, `Title`, `Description`, `Deadline`, `TaskPriority` и `TaskStatus`:

```go
--8<-- "examples/tasks-service/internal/domain/task.go:value_objects"
```

### Ключевые проектные решения в Value Objects:
1. **Подсчёт символов в UTF-8 (`Title`)**:
   Для проверки длины строки используется `utf8.RuneCountInString(trimmed)`, а не `len(trimmed)`. В кодировке UTF-8 русские буквы занимают по 2 байта, поэтому вызов `len("Лабораторная")` вернёт 24 байта вместо 12 символов.
2. **Нормализация времени (`Deadline`)**:
   Все даты приводятся к единому часовому поясу `UTC()` (`t.UTC()`). При создании новой задачи проверяется условие `!utcTime.After(utcNow)`.
3. **Метод `ReconstituteDeadline`**:
   При чтении ранее созданной задачи из базы данных дедлайн уже может находиться в прошлом (просроченная задача). Метод `ReconstituteDeadline` восстанавливает объект без проверки `After(now)`.
4. **Метод `IsZero()`**:
   Каждый Value Object реализует метод `IsZero()`, позволяющий проверить, был ли объект корректно инициализирован через фабричную функцию.

## 3. Агрегат `Task` (Доменная сущность)

Сущность `Task` инкапсулирует данные и защищает своё состояние от некорректных модификаций:

```go
--8<-- "examples/tasks-service/internal/domain/task.go:domain_entity"
```

### Архитектурные принципы агрегата `Task`:
1. **Приватные поля**:
   Все поля структуры `Task` (`id`, `title`, `deadline`, `status` и т.д.) начинаются с маленькой буквы. Внешний код не может изменить статус задачи напрямую (`task.status = ...`). Доступ на чтение предоставляется через геттеры.
2. **Проверка инвариантов в `NewTask`**:
   Конструктор гарантирует, что сущность не может быть создана в невалидном состоянии. Если хотя бы один Value Object пуст (`IsZero()`), возвращается ошибка.
3. **Оптимистичная блокировка (`version`)**:
   При создании задача получает `version = 1`. Сущность хранит исходную загруженную версию. Репозиторий при сохранении атомарно сверяет версии (`WHERE id = $1 AND version = $2`) и инкрементирует её, что надёжно защищает от состояния гонки и потерянных обновлений (Lost Updates) при параллельных запросах.
4. **Разделение прав (`IsOwnedBy`) и мутаций (`Complete`)**:
   Методы `Complete()` и `Reschedule()` не принимают параметр `actor`. Авторизация (принадлежность задачи пользователю) проверяется в слое Use Case через вызов `t.IsOwnedBy(actor)`. Сам же агрегат отвечает исключительно за собственное состояние.

## 4. Доменные события (`TaskCreated`)

Когда задача успешно создана, система фиксирует это событием:

```go
--8<-- "examples/tasks-service/internal/domain/task.go:domain_events"
```

Событие неизменяемо, содержит точный момент времени `OccurredAt` и уникальный `EventID`, генерируемый инфраструктурным генератором.

## 5. Антипаттерны: как нельзя и как правильно

### ❌ Как нельзя:
```go
// ОШИБКА 1: Публичные поля и отсутствие валидации
type Task struct {
    ID     string
    Status string // Любой код может присвоить task.Status = "HACKED"
}

// ОШИБКА 2: Ошибка подсчета байт вместо рун
if len(title) < 3 { // На кириллице слово "Да" занимает 4 байта и проходит валидацию!
    return ErrEmptyTitle
}

// ОШИБКА 3: Использование time.Now() напрямую внутри сущности
func (t *Task) Reschedule(d time.Time) error {
    if d.Before(time.Now()) { // Невозможно протестировать детерминированно!
        return ErrInvalidDeadline
    }
}
```

### ✅ Как правильно:
```go
// Приватные поля + Value Objects + инкапсуляция
type Task struct {
    id     TaskID
    status TaskStatus
}

// Передача 'now' извне через порт Clock
func (t *Task) Reschedule(newDeadline Deadline, now time.Time) error {
    if !newDeadline.Time().After(now.UTC()) {
        return ErrInvalidDeadline
    }
    t.deadline = newDeadline
    return nil
}
```

---

## Резюме

1. Доменный слой автономен и не зависит от баз данных, транспорта или фреймворков.
2. Value Objects исключают невалидные состояния строк и дат.
3. Агрегат `Task` защищает инварианты и поддерживает версионирование `version` для оптимистичной блокировки.
