# 6.4 Транспорт gRPC (Хендлеры и маппинг контрактов)

Транспортный слой — это входной адаптер (Driving Adapter) микросервиса. Он принимает бинарные запросы клиентов по протоколу HTTP/2 (gRPC), валидирует транспортные структуры Protobuf DTO, вызывает соответствующий Use Case и преобразует результат в ответ.

В Orbit AI транспортный слой строго отделён от бизнес-логики: в хендлерах **запрещено** обращаться к базам данных или проверять бизнес-правила.

---

## 1. Структура `TaskHandler`

Хендлер gRPC объединяет сценарии использования, полученные через конструктор (Dependency Injection):

```go
--8<-- "examples/tasks-service/internal/transport/taskgrpc/handler.go:grpc_handler"
```

### Ключевые паттерны `TaskHandler`:
1. **Встраивание `UnimplementedTaskServiceServer`**:
   Гарантирует прямую совместимость (Forward Compatibility). Если в `.proto`-файл будет добавлен новый RPC-метод, сервис продолжит компилироваться, возвращая для нереализованного метода код `codes.Unimplemented`.
2. **Безопасная инициализация логгера (`io.Discard`)**:
   Если в конструктор передан `nil` логгер (например, в unit-тестах), хендлер инициализирует логгер в `io.Discard`, предотвращая `nil pointer dereference`.
3. **Извлечение субъекта авторизации (`ActorFromContext`)**:
   Каждый метод извлекает `actor domain.OwnerID` из контекста запроса, гарантируя, что все дальнейшие операции выполняются от имени аутентифицированного пользователя.

---

## 2. Валидация входных Protobuf DTO

Протокол Protobuf выполняет сериализацию, но не проверяет семантику данных. Хендлер валидирует транспортные типы до вызова сценария:

```go
// 1. Проверка наличия поля дедлайна
if req.GetDeadline() == nil {
    return nil, status.Error(codes.InvalidArgument, "дедлайн задачи обязателен")
}

// 2. Валидация корректности формата Timestamp Google
if err := req.GetDeadline().CheckValid(); err != nil {
    return nil, status.Error(codes.InvalidArgument, "некорректный формат дедлайна (timestamppb)")
}

// 3. Нормализация к UTC
deadlineUTC := req.GetDeadline().AsTime().UTC()
```

## 3. Маппинг данных между DTO и доменом (Mappers)

Доменные сущности и сгенерированные Protobuf-структуры живут в разных мирах. Пакет `taskgrpc` содержит функции явного маппинга:

```go
--8<-- "examples/tasks-service/internal/transport/taskgrpc/handler.go:grpc_mappers"
```

### Обработка перечислений (Enums):
Если клиент передал значение `0` (`TASK_PRIORITY_UNSPECIFIED`) или неизвестное число, функция `protoToDomainPriority` не подставляет дефолтный приоритет «молча», а возвращает клиенту ошибку `InvalidArgument`:

```go
case tasksv1.TaskPriority_TASK_PRIORITY_UNSPECIFIED:
    return domain.TaskPriorityUnspecified, status.Error(codes.InvalidArgument, "приоритет задачи обязателен и не может быть UNSPECIFIED")
```

## 5. Антипаттерны: как нельзя и как правильно

### ❌ Как нельзя:
```go
// ОШИБКА 1: Бизнес-логика внутри gRPC хендлера
func (h *TaskHandler) CompleteTask(ctx context.Context, req *tasksv1.CompleteTaskRequest) (*tasksv1.CompleteTaskResponse, error) {
    // Прямой SQL-запрос к базе прямо в транспорте!
    db.Exec("UPDATE tasks SET status = 'COMPLETED' WHERE id = $1", req.Id)
}

// ОШИБКА 2: Использование Protobuf структур внутри сущностей домена
package domain
type Task struct {
    Deadline *timestamppb.Timestamp // Нарушение: домен зависит от стороннего proto пакета!
}
```

### ✅ Как правильно:
```go
// Хендлер только распаковывает запрос и вызывает Use Case:
func (h *TaskHandler) CompleteTask(ctx context.Context, req *tasksv1.CompleteTaskRequest) (*tasksv1.CompleteTaskResponse, error) {
    actor, err := ActorFromContext(ctx)
    if err != nil {
        return nil, err
    }

    task, err := h.completeUC.Execute(ctx, actor, req.GetId())
    if err != nil {
        return nil, h.mapError(ctx, err)
    }

    return &tasksv1.CompleteTaskResponse{Task: domainToProtoTask(task)}, nil
}
```

---

## Резюме

1. Транспортный слой — тонкий адаптер, не содержащий бизнес-правил.
2. Входящие DTO валидируются до вызова домена (`CheckValid()`, проверка `nil`).
3. Значение `UNSPECIFIED` перечислений возвращает явную ошибку `InvalidArgument`.
4. Ошибки транслируются через `mapError` со скрытием деталей внутренних аварий.
