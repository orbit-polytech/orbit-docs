# 6.7 Практикум рефакторинга: антипаттерны архитектуры

В этой главе собран каталог типичных архитектурных ошибок, возникающих при разработке микросервисов на Go, и показан их пошаговый рефакторинг к стандартам Orbit AI.

Для каждого случая приведена пара **«Как нельзя / Как правильно»**.

---

## 1. Анемичная модель данных против Богатой модели (DDD)

### ❌ Как нельзя (Anemic Domain Model):
Сущность представляет собой простую структуру с публичными полями («мешок с данными»). Вся бизнес-логика размазана по сервисам и хендлерам:

```go
// ПЛОХО: Сущность не защищает свои инварианты
type Task struct {
    ID       string
    Deadline time.Time
    Status   string
}

// В хендлере или сервисе:
if task.Status != "COMPLETED" {
    task.Status = "COMPLETED" // Любой разработчик может забыть эту проверку в другом месте
}
```

### ✅ Как правильно (Rich Domain Model):
Поля инкапсулированы (приватны), мутации возможны только через методы агрегата, проверяющие бизнес-правила:

```go
// ХОРОШО: Инварианты защищены внутри агрегата
type Task struct {
    id     TaskID
    status TaskStatus
}

func (t *Task) Complete() error {
    if t.status == TaskStatusCompleted {
        return ErrTaskAlreadyCompleted
    }
    t.status = TaskStatusCompleted
    t.version++
    return nil
}
```

## 2. Утечка инфраструктуры и транспорта в доменное ядро

### ❌ Как нельзя:
Доменная модель импортирует внешние пакеты баз данных, сериализации или транспорта:

```go
// ПЛОХО: Домен зависит от деталей хранения и сетевого протокола
package domain

import (
    "github.com/jackc/pgx/v5"
    "google.golang.org/protobuf/types/known/timestamppb"
)

type Task struct {
    ID       string                 `json:"id" db:"task_id"`
    Deadline *timestamppb.Timestamp // Зависимость от Protobuf в ядре!
}
```

### ✅ Как правильно:
Домен зависит только от `$gostd`. Теги JSON/DB и структуры Protobuf вынесены в слои инфраструктуры и транспорта:

```go
// ХОРОШО: Чистый Go в домене
package domain

type Task struct {
    id       TaskID
    deadline Deadline // Value Object на базе time.Time
}
```

## 3. «Толстый» монолитный репозиторий против ISP

### ❌ Как нельзя:
Один гигантский интерфейс `TaskRepository` на десятки методов передаётся во все сценарии:

```go
// ПЛОХО: Нарушение Interface Segregation Principle
type TaskRepository interface {
    Save(ctx context.Context, t *Task) error
    FindByID(ctx context.Context, id string) (*Task, error)
    List(ctx context.Context, filter Filter) ([]*Task, error)
    Delete(ctx context.Context, id string) error
    Archive(ctx context.Context, id string) error
    CountByStatus(ctx context.Context, status string) (int, error)
}

// Сценарию GetTaskUseCase нужен только FindByID, но он зависит от всех 6 методов!
```

### ✅ Как правильно:
Узкие интерфейсы (порты), объявленные потребителем:

```go
// ХОРОШО: Сценарий объявляет только то, что ему реально нужно
type TaskFinder interface {
    FindByID(ctx context.Context, id domain.TaskID) (*domain.Task, error)
}

type GetTaskUseCase struct {
    finder TaskFinder
}
```

## 4. Тихие умолчания против принципа Fail-Fast

### ❌ Как нельзя:
При получении некорректных параметров сервис «молча» подставляет дефолты или проглатывает ошибки:

```go
// ПЛОХО: Тихая маскировка ошибок
func ListTasks(limit, offset int) {
    if limit <= 0 {
        limit = 20 // Клиент передал мусор, а сервер делает вид, что все нормально
    }
}

func ParsePriority(raw int) domain.Priority {
    if raw == 0 {
        return domain.PriorityLow // Неопределенный enum превратился в LOW
    }
}
```

### ✅ Как правильно:
Явная валидация и возврат ошибки `InvalidArgument`:

```go
// ХОРОШО: Строгая валидация контракта
if limit <= 0 || limit > 100 {
    return nil, 0, fmt.Errorf("%w: лимит %d обязан быть в диапазоне [1, 100]", domain.ErrInvalidPagination, limit)
}

if priority == tasksv1.TaskPriority_TASK_PRIORITY_UNSPECIFIED {
    return domain.TaskPriorityUnspecified, status.Error(codes.InvalidArgument, "приоритет не может быть UNSPECIFIED")
}
```

## 5. Раскрытие информации (IDOR) против сокрытия ресурса

### ❌ Как нельзя:
При попытке открыть чужую задачу сервер сообщает клиенту `PermissionDenied` (403):

```go
// ПЛОХО: Уязвимость перебора сущностей (IDOR)
task, _ := repo.FindByID(id)
if task.OwnerID != actor {
    return status.Error(codes.PermissionDenied, "доступ запрещен: это не ваша задача")
    // Злоумышленник понял: задача с таким ID существует!
}
```

### ✅ Как правильно:
Централизованный `loadOwned` возвращает `NotFound` (404):

```go
// ХОРОШО: Для постороннего пользователя чужая задача неотличима от несуществующей
func loadOwned(ctx context.Context, f TaskFinder, actor domain.OwnerID, rawID string) (*domain.Task, error) {
    task, err := f.FindByID(ctx, taskID)
    if err != nil {
        return nil, err
    }
    if !task.IsOwnedBy(actor) {
        return nil, domain.ErrTaskNotFound // Сокрытие существования ресурса
    }
    return task, nil
}
```

## 6. Мутация разделяемой памяти против глубокого клонирования

### ❌ Как нельзя:
In-memory репозиторий отдаёт вызывающему коду оригинальный указатель:

```go
// ПЛОХО: Утечка разделяемой памяти и гонка данных
func (r *Repo) FindByID(id string) *domain.Task {
    r.mu.RLock()
    defer r.mu.RUnlock()
    return r.tasks[id] // Возврат оригинала из мапы!
}
```

### ✅ Как правильно:
Глубокое клонирование сущности через конструктор восстановления:

```go
// ХОРОШО: Изоляция указателей
func (r *TaskRepository) FindByID(ctx context.Context, id domain.TaskID) (*domain.Task, error) {
    r.mu.RLock()
    defer r.mu.RUnlock()
    task, exists := r.tasks[id.String()]
    if !exists {
        return nil, domain.ErrTaskNotFound
    }
    return cloneTask(task), nil
}
```

## 7. Паника вместо ошибки при генерации идентификаторов

### ❌ Как нельзя:
Использование методов вида `uuid.Must()`:

```go
// ПЛОХО: Сервис падает в продакшене при сбое системной энтропии
func GenerateID() string {
    return uuid.Must(uuid.NewRandom()).String() // panic!
}
```

### ✅ Как правильно:
Возврат явной ошибки `error`:

```go
// ХОРОШО: Явная обработка ошибки генератора
func (g *UUIDGenerator) NewTaskID() (domain.TaskID, error) {
    newUUID, err := uuid.NewRandom()
    if err != nil {
        return domain.TaskID{}, fmt.Errorf("ошибка генерации UUID: %w", err)
    }
    return domain.NewTaskID(newUUID.String())
}
```

## Резюме

Соблюдение этих правил гарантирует, что сервисы Orbit AI:
1. Защищены от распространенных уязвимостей (IDOR, Information Disclosure).
2. Не падают от непредвиденных паник и утечек памяти.
3. Имеют предсказуемый контракт без тихих искажений пользовательских данных.
